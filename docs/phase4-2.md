# DEBA Phase 4.2 — Deal Matching & Price Intelligence\n\n## Dynamic deal intelligence\n\npublic.get_product_deal_score(product_id) compares a published, approved sale listing against comparable listings in the same currency, category, and condition.\nIt returns average, median, P25, P75, peer count, price delta, a bounded 0–100 score, a confidence estimate, and a graph payload.\n\nLabel contract:\n- great_deal: at least 15% below comparable average.\n- fair: from -15% through +10%.\n- overpriced: more than 10% above comparable average.\n- insufficient_data: fewer than 3 qualified peers.\n\nNo model-generated or hard-coded market prices are used.\n\n## Buyer Intent Matching\n\nAuthenticated users can save a query + filters through /api/buyer-intent/saved-searches.\nThe engine persists owner-scoped product matches in public.buyer_intent_matches and exposes them through /api/buyer-intent/matches.\nWhen a product transitions into public published/approved state, PostgreSQL can asynchronously call the internal matcher through pg_net when Vault endpoint/secret are configured.\n\nVault values:\n- deba_buyer_intent_webhook_url\n- deba_buyer_intent_webhook_secret\n\nServer environment:\n- DEBA_BUYER_INTENT_WEBHOOK_SECRET\n\nAutomatic matching is intentionally no-op until endpoint/secret are configured.\n\n## Verification\n- npm run typecheck\n- npm test\n- npm run test:phase4-2\n- Apply the migration only after review; then run a live authenticated match test and a live deal-score RPC check.
